# 人机共享判断规则库 (`Judgment Rules`)

> **定位**：这里不记流水账日志，只记跨项目通用的 **「如果遇到什么信号 → 真实原因是什么 → 应该立刻做什么」**。每次协作踩出新认知，在此追加一条。

---

## 一、 识别「假完成」的判断规则

- **如果** 子代理汇报「功能已完成、单测全绿」 → **则** 只能视为「代码编译与局部逻辑通过」，必须检查是否测过契约入参/空参边界，且最终向人类提供真实入口体验步骤后才算交付。
- **如果** 工具/接口接入后出现「调用了但全报错」 → **则** 优先排查入参/出参 Schema 契约不匹配或异步未 `return await` 裸抛异常，先补一条契约冒烟测试。
- **如果** 页面或导出结果看起来能跑但「不好用」 → **则** 90% 是漏了「数据质量断言」（如兜底逻辑把裸 URL 当标题、重复记录未去重）或缺少加载/进度状态反馈，而非主逻辑没写。

---

## 二、 防「重复造轮子」的判断规则

- **如果** 准备动手写解析器、格式转换、搜索聚合、标准引用/协议处理 → **则** 立刻停手，先查本项目依赖表 + 用 `search_web` 搜索成熟开源库；自研解析器的边界 Bug 密度远高于工业库。
- **如果** 自己写了一版逻辑，已经连续第 2 轮在修各种奇葩边界（Edge Case） → **则** 这是典型的「造轮子信号」，停下来评估直接替换为成熟库适配层（Adapter）。

---

## 三、 交互与产品分工的判断规则

- **如果** 对某个交互细节（触发时机、面板布局、快捷操作）拿不准 → **则** 不要拍脑袋发明交互，先用 `search_web` 找 2～3 款同类标杆产品看它们怎么处理，给人类做选择题。
- **如果** 功能同时包含「探索/生成/问答过程」和「资产管理/配置/阅读」 → **则** 动态研究过程放对话流，沉淀下来的库/阅读/配置放侧栏或独立面板，不要混塞在一处。
- **如果** 一个新功能需要「让用户先去设置里翻找某个隐蔽开关才能用」 → **则** 默认交互体验不合格，应做到开箱即用或就地引导。

---

## 四、 多项目管理与防上下文错乱规则

- **如果** 单个子代理会话已经经历了多轮报错排障、上下文明显变厚 → **则** 将阶段结论写入 `boards/<slug>.md` 后主动结束该会话，下一阶段拉起全新子代理轻装上阵（“铁打的记忆卡，流水的会话”）。
- **如果** 子代理进场发现项目目录有未提交的人类手写改动 → **则** 先读懂人类改动的意图并顺势接力，绝不执行覆盖式重置（如 `git checkout --` / `git reset --hard`）。
- **如果** 在早已打开的老对话窗口接到新一轮任务 → **则** 动手前必须重新 `read_file` 拉取最新的 `boards/<slug>.md`（及 `DASHBOARD.md`），严禁依赖本窗口早先轮次的旧快照而漏掉并行窗口刚落盘的进展。
- **如果** 编写 PreToolUse 护栏识别会话身份或高危命令 → **则** 必须按协议结构化解析（只认 JSONL 出生输入与真实 Shell 子命令 token，并把活跃工作区根下的目录从系统 `/tmp` 豁免中排除），严禁对原始日志或整行文本做无差别子串盲搜，否则必触发文档读取自锁、公共看板串台或测试穿透。
- **如果** Python CLI 入口脚本（作为 `__main__` 运行）导入了反向 `import` 该入口模块的子模块 → **则** 必须在入口脚本顶部先执行 `sys.modules.setdefault("<module>", sys.modules[__name__])` 对齐模块身份，且单测必须包含真实 `subprocess.run` 子进程异常路径断言，避免进程内测试掩盖异常类型不一致导致的未捕获 Traceback。
