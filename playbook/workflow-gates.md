# 人机协作标准开发链路与门禁 (`Workflow Gates`)

源自实战复盘沉淀：不求形式官僚，只卡真正会导致返工和假完成的致命节点。

---

## 一、 六步人机接力链路

```text
[A 立项边界]  ──(人拍方向)──►  要不要做、交付形态与宿主约束写清
      │
      ▼
[B 规格与参考] ──(本地 research 查依赖 + search_web 扫开源/竞品 → 人定方案)──► 禁止跳过！先搜现成库、横评交互
      │
      ▼
[C 弹性实现]  ──(按 G1/G2/G3 调动 @planner + @impl/@author-*)──► 功能完整 → 体验顺畅 → 视觉对齐
      │
      ▼
[D 独立盲测]  ──(全新独立 @verifier 执行五层对抗盲测 + 红测锁断言)──► PASS 准出
      │
      ▼
[E 真实体验]  ──(人握最终验收权)──► 按「3步体验指引」在真实环境点一遍才算完成
      │
      ▼
[F 复盘沉淀]  ──(人机共创资产)──► 好方法进工具箱/技能，新踩坑写成「如果…则…」进规则库
```

## 二、 开工前必查（B 阶段门禁）

在让 `[HUB_ROLE:IMPL]` 动手写第一行核心业务代码前，Hub 总控（Coordinator）必须确认以下 4 件事已有明确答案（缺项则先派只读调研汇报人类）：

1. **交付约束清晰吗？**（运行环境、宿主集成规范、跨平台兼容边界、不伤宿主现有能力）
2. **核心能力搜过现有依赖和开源了吗？**
   - 先派本地只读 `research` 子代理查当前项目的 `package.json` / `pyproject.toml` 是否已经装了同类库却没用；
   - 凡涉及「解析器、检索聚合、格式转换/导出、标准协议/鉴权」，调用内置 `search_web` 扫描成熟开源备选，禁止上来手搓。
3. **交互参考过同类成熟产品吗？**
   - 拿不准交互密度（如弹窗、划词、侧栏 vs 主区）时，调用 `search_web` 检索 2～3 个成熟产品的做法做横评，由人选定后再画 UI。
4. **可量化验收标准（DoD）写出来了吗？**
   - 明确改完后跑哪条命令、测哪几个空参/坏输入边界、人类怎么在真实界面/CLI 3 步验证。

## 三、 独立验收五层检查表（D 阶段必检）

`[HUB_ROLE:VERIFIER]` 严禁只跑一句 `npm test` 或 `pytest` 看到绿灯就宣布通过，必须按任务类型覆盖对应五层：

| 层次 | 检查重点 | 常见漏测症状 |
| :--- | :--- | :--- |
| **1. 代码与红线审查** | `git diff` 范围、受保护契约、是否偷改测试断言、无残留临时文件 | 顺手重构无关文件或修改断言骗绿灯 |
| **2. 确定性测试实跑** | 类型检查、单测与回归脚本实跑，记录退出码与 `pass/fail/skip` | 把 `skip` 当通过，或仅口头声称测试已跑通 |
| **3. 契约与坏输入探测** | 入参/出参 Schema、空参、`null`/畸形数据、异常捕获与零 Traceback | 单测全绿，一上真实对话/前端调用或异常输入就崩 |
| **4. 数据质量与体感** | 输出字段是否干净可读、有无脏数据/重复条目、长耗时有无状态反馈 | 能跑通但产出的内容不可直接用 |
| **5. 真实入口冒烟** | 从用户实际使用的入口（UI 页面 / 真实 CLI 子进程）走通一遍 | 只有内存测试桩能调通，真实命令或页面点不通 |

---

## 四、 硬禁止清单

- ❌ 未检查项目已有依赖、未搜成熟开源就自研解析/检索/转换逻辑
- ❌ 写代码的同一个会话自己宣布「已测试通过」（凡核心改动必须经独立 `@verifier` 会话核验）
- ❌ 用兜底脚本或 mock 数据冒充「真实链路已通」
- ❌ 跳过功能与体验，提前在花哨自定义样式上消耗工时（UI 优先复用宿主原生设计 Token）
- ❌ 把大段调试报错塞进 `DASHBOARD.md` 或 `boards/*.md` 污染外置记忆
